We thank the Reviewer for requesting explicit validation of the release mechanism. We have now performed controlled tests of the deployed CCD file-delivery handler on the development host and added the test procedure, results, and limitations to the revised manuscript.

The test used a synthetic FITS product containing two image HDUs with nonzero integer and floating-point arrays. The handler code was extracted directly from the deployed resource descriptor. With a fixed release date, a controlled clock simulated the day before release, the release date, and the following day; a database test double supplied the unchanged product record. Before release, both arrays were zero-valued. On and after release, the returned file was byte-identical to the original. Header blocks were preserved in every case, and the source file remained unchanged. Returning the clock to the pre-release date reproduced the masked output. All four checks passed.

Separately, two HTTP regression tests against the running development service passed, confirming SIAP metadata retrieval and masked delivery of an embargoed image. We explicitly distinguish these checks from an observed release event across an actual date boundary, which has not yet been demonstrated. The Conclusions have been revised accordingly.

The validation script, extracted service handler, recorded controlled-test results, and reproduction instructions are publicly available in the project repository under `validation/embargo_release`. The original full resource descriptor is identified by its SHA-256 hash; the published service excerpt preserves both executable code blocks unchanged.
