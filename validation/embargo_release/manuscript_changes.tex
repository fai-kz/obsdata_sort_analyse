\textcolor{blue}{For the CCD archive, discovery metadata remain queryable during embargo, while access to the original FITS data is controlled by the DaCHS product infrastructure and the dedicated \texttt{zeroed} delivery service. The delivery handler reads the product's embargo date from \texttt{dc.products} and selects either the masked representation or the original file according to the current server date. This request-time delivery check is distinct from SQL date filters used to select records in the browsing interface. The release logic and its controlled validation are described in Section~\ref{subsec:embargo_enforcement}.}

\textcolor{blue}{The masking mechanism protects the data arrays during embargo; the request-time selection between masked and original content is described and evaluated below.}

\textcolor{blue}{The CCD file-delivery service determines access at request time using the embargo date stored in \texttt{dc.products}. The Python handler compares this date with the current server date obtained through \texttt{datetime.date.today()}. Before the release date, the service returns a zero-filled Showcase FITS; on or after that date, it selects the original FITS file without requiring a manual change of access status.}

\textcolor{blue}{We evaluated this release logic on the development host using the handler code extracted directly from the deployed resource descriptor. A synthetic FITS file contained two image HDUs with nonzero 16-bit integer and 32-bit floating-point arrays. The release date remained fixed, while a controlled test clock represented the day before release, the release date itself, and the following day. Database lookup was replaced by a test double returning the same synthetic product and embargo date throughout the test.}

\textcolor{blue}{All three date cases passed: before release, both image arrays were zero-valued; on and after release, the returned file was byte-identical to the original. FITS header blocks were preserved byte-for-byte in all cases, and the source file remained unchanged. An additional check returning the test clock to the pre-release date reproduced the masked output. Separately, two HTTP regression tests against the running development service passed, confirming SIAP metadata retrieval and masked delivery of an embargoed image.}

\textcolor{blue}{These results validate the handler's release-date logic under controlled conditions and the separately tested HTTP operations. They do not constitute an observed release event across an actual date boundary in the running service. The validation script, extracted service handler, recorded controlled-test results, and reproduction instructions are available in the project repository \citep{fai_sort_repo}, under \texttt{validation/embargo\_release}.}
